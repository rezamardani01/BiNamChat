## معرفی

**بینام** یک ربات فارسی برای پیام‌رسان بله است. کاربران می‌توانند پروفایل بسازند، ناشناس با دیگران گفت‌وگو کنند و با لینک اختصاصی پیام بگیرند. مدیریت کاربران و تنظیمات ربات نیز از طریق پنل داخل بله انجام می‌شود.

## امکانات

- گفت‌وگوی ناشناس تصادفی با فیلترهای جست‌وجو
- لینک اختصاصی برای دریافت پیام ناشناس
- پروفایل، فهرست دوستان و ارتباط با کاربران
- گزارش و مسدودکردن کاربران
- کیف پول، سکه و حساب ویژه
- پنل مدیریت برای تنظیمات، کاربران، گزارش‌ها و پیام همگانی
- ذخیره‌سازی محلی اطلاعات با SQLite
- ثبت گزارش اجرا برای عیب‌یابی

## فناوری‌ها

| فناوری | کاربرد |
|---|---|
| [baleropy](https://pypi.org/project/baleropy/) | ارتباط با Bot API پیام‌رسان بله |
| [aiosqlite](https://pypi.org/project/aiosqlite/) | کار ناهمگام با پایگاه داده |
| SQLite | ذخیره‌سازی داده‌ها در فایل محلی |
| Python 3.10+ | زبان و محیط اجرای پروژه |

## پیش‌نیازها

- Python نسخهٔ **۳٫۱۰ یا جدیدتر**
- دسترسی شبکهٔ سرور به API پیام‌رسان بله
- توکن ربات بله و شناسهٔ عددی مالک

## اجرای محلی

### ۱. دریافت پروژه

```bash
git clone https://github.com/rezamardani01/BiNamChat.git
cd BiNamChat
python -m venv .venv
```

محیط مجازی را فعال کنید:

**ویندوز (PowerShell):**

```powershell
.\.venv\Scripts\Activate.ps1
```

**لینوکس یا macOS:**

```bash
source .venv/bin/activate
```

### ۲. نصب وابستگی‌ها

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### ۳. تنظیم ربات

فایل `config.py` در ریشهٔ پروژه قرار دارد. مقدارهای خالی آن را با اطلاعات ربات خودتان تکمیل کنید:

```python
TOKEN = "توکن دریافتی از BotFather بله"
OWNER_ID = 123456789  # شناسهٔ عددی مالک؛ بدون کوتیشن
```

- توکن را از **BotFather بله** دریافت کنید.
- `OWNER_ID` باید شناسهٔ عددی حساب مالک باشد، نه نام کاربری.
- توکن واقعی را در GitHub یا هیچ مخزن عمومی دیگری قرار ندهید. `config.py` در این پروژه نسخهٔ خالی نمونه است؛ مقدارهای واقعی را فقط در نسخهٔ محلی وارد کنید.

### ۴. اجرا

```bash
python run.py
```

در اجرای نخست، دیتابیس و گزارش‌ها در پوشهٔ `data` ساخته می‌شوند. برای توقف اجرای محلی `Ctrl+C` را بزنید.

## نصب روی هاست اشتراکی

> **مهم:** این پروژه یک ربات **long-polling** است، نه وب‌سایت یا برنامهٔ WSGI. صرفِ پشتیبانی هاست از Python کافی نیست؛ شرکت هاستینگ باید اجرای دائمی پردازش پس‌زمینه و اتصال خروجی به API بله را مجاز بداند. پیش از خرید یا نصب، این موضوع را از پشتیبانی هاست بپرسید. قابلیت **Setup Python App / Passenger** در cPanel به‌تنهایی برای اجرای این ربات مناسب نیست.

### شرایط لازم هاست

- Python نسخهٔ ۳٫۱۰ یا جدیدتر و دسترسی به Terminal یا SSH
- امکان ساخت و استفاده از `venv` و نصب بسته‌ها با `pip`
- اجازهٔ اجرای پردازش پایتون به‌صورت دائمی (persistent/background process)
- اجازهٔ اتصال خروجی HTTPS به سرویس بله
- فضای قابل‌نوشتن برای دیتابیس و گزارش‌ها

اگر هاست اجرای دائمی پردازش‌ها را متوقف می‌کند، این ربات روی آن پایدار نمی‌ماند؛ در این صورت از سرویس میزبانی دارای worker دائمی یا VPS استفاده کنید. نسخهٔ فعلی برای webhook و اجرای WSGI آماده نشده است.

### مراحل نصب با Terminal یا SSH

#### ۱. اتصال و بررسی Python

از بخش **Terminal** در cPanel یا با SSH وارد سرور شوید. دستورهای زیر را اجرا کنید و مطمئن شوید نسخهٔ Python حداقل ۳٫۱۰ است:

```bash
python3 --version
```

پروژه را بیرون از `public_html` دریافت کنید تا فایل تنظیمات و دیتابیس از مسیر وب قابل‌دسترسی نباشند:

```bash
cd "$HOME"
git clone https://github.com/rezamardani01/BiNamChat.git
cd BiNamChat
```

#### ۲. ساخت محیط مجازی و نصب کتابخانه‌ها

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

اگر `python3` به نسخهٔ موردنیاز اشاره نمی‌کند، نام دستور نسخه‌ای را که شرکت هاست ارائه کرده جایگزین کنید؛ برای نمونه `python3.11`.

#### ۳. تنظیم توکن و مالک

فایل `config.py` را با ویرایشگر Terminal یا File Manager ویرایش کنید و مقدارهای معتبر را وارد کنید:

```python
TOKEN = "توکن ربات بله"
OWNER_ID = 123456789
```

مطمئن شوید فایل در ریشهٔ پروژه است و پروژه داخل `public_html` قرار نگرفته است. توکن را برای پشتیبانی یا افراد دیگر ارسال نکنید.

#### ۴. اجرای آزمایشی

ابتدا در همان نشست SSH و در حالت foreground اجرا کنید:

```bash
python run.py
```

اگر پیام روشن‌شدن ربات را در بله دریافت کردید، اجرا موفق بوده است. با `Ctrl+C` اجرای آزمایشی را متوقف کنید.

#### ۵. اجرای پس‌زمینه (فقط اگر هاست مجاز می‌داند)

اگر شرکت هاستینگ صراحتاً پردازش پس‌زمینهٔ دائمی را مجاز می‌داند، از ریشهٔ پروژه اجرا کنید:

```bash
mkdir -p data
nohup "$HOME/BiNamChat/.venv/bin/python" "$HOME/BiNamChat/run.py" \
  >> "$HOME/BiNamChat/data/console.log" 2>&1 &
echo $! > "$HOME/BiNamChat/data/bot.pid"
```

برای مشاهدهٔ گزارش اجرا:

```bash
tail -f "$HOME/BiNamChat/data/console.log"
```

برای توقف پردازش اجراشده با دستور بالا:

```bash
kill "$(cat "$HOME/BiNamChat/data/bot.pid")"
```

برخی هاست‌ها بعد از خروج از SSH، ری‌استارت سرور یا عبور از محدودیت مصرف منابع، پردازش را متوقف می‌کنند. `nohup` این محدودیت‌های هاست را دور نمی‌زند و راه‌اندازی مجدد خودکار هم فراهم نمی‌کند. اگر این محدودیت‌ها وجود دارد، از میزبان دارای worker دائمی استفاده کنید.

## ساختار پروژه

```text
BiNamChat/
├── config.py          # تنظیمات ربات؛ نسخهٔ مخزن بدون توکن واقعی
├── data/
│   └── geo.json       # فهرست استان‌ها و شهرها
├── run.py             # نقطهٔ شروع اجرا
├── requirements.txt   # وابستگی‌های Python
└── src/
    ├── admin/         # پنل مدیریت
    ├── handlers/      # مدیریت رویدادها و پیام‌ها
    └── ...            # هسته، دیتابیس و منطق برنامه
```

## عیب‌یابی

| پیام یا مشکل | راهکار |
|---|---|
| درخواست واردکردن `TOKEN` | مقدار `TOKEN` را در `config.py` بررسی کنید. |
| خطای `OWNER_ID` | شناسه باید عدد صحیح مثبت باشد و کوتیشن نداشته باشد. |
| نصب نشدن وابستگی‌ها | فعال‌بودن محیط مجازی و سازگاری نسخهٔ Python را بررسی کنید. |
| ربات پس از خروج از SSH خاموش می‌شود | هاست احتمالاً پردازش دائمی را پشتیبانی نمی‌کند؛ از پشتیبانی سؤال کنید یا میزبان دیگری انتخاب کنید. |
| خطای اتصال به بله | دسترسی خروجی HTTPS و وضعیت شبکهٔ هاست را بررسی کنید. |

## پرسش‌های رایج

### آیا قابلیت Setup Python App در cPanel کافی است؟

خیر. این قابلیت معمولاً برای برنامه‌های وب مبتنی بر WSGI است، اما بینام با long-polling اجرا می‌شود. برای اجرای آن به دسترسی Terminal یا SSH و اجازهٔ پردازش پس‌زمینهٔ دائمی نیاز دارید.

### اگر هاست بعد از بستن SSH ربات را متوقف کرد چه کنم؟

این محدودیت را نمی‌توان با `nohup` دور زد. از پشتیبانی هاست دربارهٔ worker دائمی سؤال کنید؛ اگر چنین قابلیتی ندارد، ربات را روی VPS یا سرویس میزبانی مناسب اجرا کنید.

### آیا توکن را در فایل config.py گیت‌هاب وارد کنم؟

خیر. نسخهٔ موجود در مخزن فقط مقادیر خالی دارد. توکن و شناسهٔ واقعی را فقط در فایل محلی سرور یا رایانهٔ خودتان قرار دهید و آن‌ها را commit نکنید.
